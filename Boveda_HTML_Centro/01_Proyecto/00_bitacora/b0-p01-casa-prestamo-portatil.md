## 🤔 Respuestas a las preguntas

1. Porque quería controlar solo los archivos del proyecto y no toda la bóveda.

2. Antes de `add`, mostró los archivos nuevos sin seguimiento; después de `add`, los archivos preparados para guardar; y después de `commit`, que los cambios estaban guardados.

3. Para tener una copia del proyecto en GitHub y poder subir los cambios con `git push`. `origin` identifica el repositorio remoto.

4. Porque `git status` detecta archivos nuevos, pero `git diff` no muestra normalmente el contenido de archivos que todavía no están bajo seguimiento.

5. Comprobé que los vídeos existían en la carpeta y que estaban excluidos mediante el archivo `.gitignore`.

6. Muestra un resumen de los cuatro archivos preparados, con las líneas añadidas y eliminadas.

7. Al visitar el primer commit, veo la versión inicial de la web. Al volver a `main`, recupero la versión más reciente de esa rama.

8. La web necesita historial para registrar cambios y recuperar versiones anteriores. GitHub permite compartir el proyecto y colaborar con otros técnicos.

9. Si corrijo una errata en `normas.html`, repito `git status`, `git add normas.html`, `git commit` y `git push`. No repito `git init` ni `git remote add origin` porque ya están configurados.
